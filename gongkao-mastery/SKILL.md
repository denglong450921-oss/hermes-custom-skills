# 公考题目精讲与掌握

把一道题变成一份可反复学习的中文微课程。目标不是只公布答案，而是让学习者经历“作答—诊断—理解—迁移—再测”的闭环。

## 演示文件

`assets/demo-导游自由执业-意图判断题.html` 是本技能的标准演示页面。首次使用、调整页面布局或不确定交互效果时，打开该文件作为成品参照，重点观察：

- 左侧目录与右侧内容布局；
- 原题提交前隐藏解析的“先测后学”流程；
- 正误反馈、重新作答与学习进度；
- 重点高亮、表格、复盘卡片和三类重构练习。

演示文件只用于对齐结构、视觉和交互，不要复制其中的题干、答案或解析到新题。新题仍应先完成独立分析，再使用 `scripts/renderer.py` 生成最终 HTML。

## 公考第一性原理：考试的本质

公考不是学术能力测试，而是一套**筛选与分层机制**。理解这一点，才能从命题人视角解题，而不是从考生视角猜答案。

### 考试的根本目的

公考的核心功能是：**在大量候选人中，用最低成本、最高信度地区分出不同层级的治理潜质**。每一道题都是一把筛子——它的设计目标不是"测出你懂多少"，而是"把你和与你水平相邻的人分开"。

这意味着：

- **难度 ≠ 绝对难度**。一道题是否"难"，取决于它在哪个分数段产生区分度。一道 80% 考生做对的题，对前 10% 的考生没有区分力。
- **干扰项是精密工具**。每个错误选项都针对特定水平的考生设计：A 选项筛掉完全不懂的，B 选项筛掉半懂不懂的，C 选项筛掉懂了但不够严谨的。
- **正确选项的"可辩护性"高于"显而易见性"**。公务员考试的正确答案必须经得起复议和质疑，因此它们几乎总是从材料中严格推导出来的，而不是"感觉像"。

### 第一性原理：从命题人视角倒推

把每道题还原到它的设计原点：

| 命题人的问题 | 考生应做的倒推 |
|---|---|
| 这道题要测什么能力？ | 此题考查的核心能力是什么？ |
| 正确选项的"唯一性"建立在什么证据上？ | 材料中哪句话锁定了正确答案？ |
| 每个错误选项分别"钓"哪类考生？ | 我是否曾是这类干扰项的目标？ |
| 这道题在哪个分数段产生区分度？ | 此题难度定位在哪里？我该花多少时间？ |

### 公考思维的三个层次

1. **初级：知识记忆层**——记住知识点，能识别正确选项。
2. **中级：逻辑分析层**——拆解论证结构，区分事实与观点，追踪因果链。
3. **高级：命题思维层**——理解这道题为什么这样出、干扰项为什么这样设、它在整个考试中的筛选功能是什么。

本技能的目标是帮学习者从第 1 层逐步走到第 3 层。**当你开始用命题人的眼睛看题，错误选项就不再是"陷阱"，而是透明的分类标签。**

### 题目如何区分、分层、筛选考生

每道行测题都是一次微型心理测量。理解以下机制，你就知道为什么有些题"总觉得两个选项都对"——因为你就站在那个区分边界上：

1. **区分（Distinguish）**：通过一个关键逻辑节点，把理解正确与理解偏差的人分开。
2. **分层（Stratify）**：多道题的累积效果，将考生稳定地分布到不同分数段。
3. **筛选（Screen）**：设定分数线，实现录取决策。
4. **选拔（Select）**：在分数基础上，申论和面试进一步考察治理思维、表达能力和价值观匹配。

你每做对一道"中等难度、高区分度"的题，就筛掉了几千个在同一个逻辑节点上犯错的人。**公考的竞争不是"谁更聪明"，而是"谁犯的逻辑错误更少"。**

## 工作流程

### 1. 识别与还原题目

从文字、截图或附件中提取题干、选项、材料和用户已选答案。信息不完整但仍可可靠推断时，标注“根据现有信息还原”；缺失会改变正确答案时，再向用户询问。

识别题型与考点，例如：言语理解与表达、判断推理、数量关系、资料分析、常识判断或申论。不要被材料主题牵着走，先判断命题人实际考查的能力。

### 1.5. 能力映射：这道题在考查什么政治思维

在深入解析前，先完成一道"元思考"——把本题映射到它实际考查的能力维度：

**公考六大核心能力维度：**

| 能力维度 | 典型题型 | 考查内容 | 思维特征 |
|---|---|---|---|
| 政策理解力 | 常识判断、申论材料分析 | 对政策方向、国家战略、法律法规的理解 | 能从宏观背景理解具体问题 |
| 逻辑分析力 | 判断推理、言语理解 | 论证结构识别、前提-结论追踪、逻辑漏洞检测 | 不凭感觉，只凭证据链 |
| 数据解读力 | 资料分析、数量关系 | 从数据中提取趋势、比较差异、推算结论 | 用数字说话，不是用印象说话 |
| 问题解决力 | 数量关系、申论对策 | 将现实问题转化为可操作的解决路径 | 方案可行、步骤清晰、成本可接受 |
| 表达规范力 | 言语理解、申论写作 | 公文语体、政策术语、逻辑严谨的表达 | 准确 > 优美，规范 > 个性 |
| 价值判断力 | 常识判断、申论立意 | 在复杂情境中做出符合治理伦理的判断 | 公共利益优先、程序正义、底线思维 |

**映射三问：**

1. 这道题主要考查哪个能力维度？（通常 1 个主维度 + 1 个辅助维度）
2. 命题人选这个材料/话题，想引导考生进入什么思维轨道？
3. 如果我想"伪装"成高能力考生，应该展现什么思维特征？

在后续解析中，明确标注每个选项判断所依据的能力维度。这让学习者不仅知道"哪个对"，还知道"这题在测我什么"——后者才是提分的根本。

### 2. 先测后学

HTML 首屏只展示原题和选项，不提前暴露正确答案。提供：

- 单选按钮；
- “提交答案”按钮；
- 未选择时的提示；
- 提交后的正误反馈与简短诊断；
- “进入解析”按钮，提交后才显示或跳转到解析区；
- “重新作答”按钮，清除本次选择和反馈。

Markdown 无法真正交互，因此先放“作答区”，使用折叠 `<details>` 隐藏答案和解析入口，避免打开即剧透。

### 3. 深度解析

根据题型灵活调整篇幅，但保持以下顺序：

1. 正确答案与一句话结论
2. 题目设计分析：命题人考什么
3. 文段、材料或推理结构
4. 逐项分析：为什么对、为什么错
5. 陷阱设计与错误心理
6. 标准解题过程示范
7. 快速解题方法与口诀
8. 概念理解：将具体题提升为可迁移规律
9. 题型边界与适用条件
10. 考试设计视角：这道题如何区分和筛选考生
11. 这类题目的通用逻辑框架（重点记忆模块）
12. 错误选项的通用类型（重点记忆模块）
13. 重构题与练习题
14. 最终总结与复盘卡片

“题目设计分析—能力映射—概念理解—考试设计视角—通用逻辑框架—错误选项类型—练习题”是核心，不可省略。解释必须建立逻辑层级，明确区分事实、过程、局部结论、总体结论；不要只做选项同义改写。

### 考试设计视角：这道题如何区分和筛选考生

这一节是"第一性原理"在单道题上的落地。每道题都应完成以下分析，帮助学习者理解：**为什么这道题能把我从人群中筛选出来？**

1. **难度定位**：这道题大约在什么分数段产生区分力？（入门筛 / 中等筛 / 高分筛）
2. **区分机制**：关键的逻辑分歧点在哪一步？"做对的考生"和"做错的考生"在哪个判断上分道扬镳？
3. **干扰项的筛选功能**：
   - 哪些干扰项筛掉完全不理解材料的考生？
   - 哪些干扰项筛掉理解片面/过度推断的考生？
   - 哪些干扰项筛掉逻辑严谨但方向偏了的考生？
4. **正确选项的"可辩护性"**：正确答案从材料的哪些证据中推导出来？为什么它经得起质疑而其他选项做不到？
5. **时间策略**：这道题在考试中应该花多少秒？如何在速度和准确率之间做最优权衡？

使用一个**区分度表格**概括：

| 选项 | 筛选目标 | 典型错误思维 | 区分层次 |
|---|---|---|---|
| A | XX 类考生 | XX 思维 | 入门筛 |
| B | XX 类考生 | XX 思维 | 中等筛 |
| C（正确）| 高能力考生 | — | 高分筛 |
| D | XX 类考生 | XX 思维 | 入门筛 |

### 重点记忆模块：十一、通用逻辑框架

这一节回答“以后遇到同类题，如何一眼认出骨架”。写得比普通解析更详细，并采用以下固定教学顺序：

1. **具体题抽象化**：先把本题信息压缩成 3—5 个逻辑节点，例如“措施 → 机制 → 直接效果 → 总体价值”。
2. **槽位定义**：逐一解释每个节点的含义、识别信号和它在选项中的常见表达。
3. **双重编码**：同一框架同时用“箭头链/结构图”和“对照表”呈现，让文字规则与视觉位置互相提示。
4. **适用边界**：给出何时可套用、何时不可套用，避免把口诀机械化。
5. **跨主题迁移**：至少给出 3 个不同领域的迷你例子，其中一个应是反例或边界例。
6. **生成式填空**：先让考生补全框架，再揭晓答案；利用生成效应强化编码。
7. **一句话提取线索**：用不超过 20 字的口诀或检索提示收束，并确保能还原解题动作。

通用框架不能只写一个箭头公式。它至少要回答：每一层是什么、如何识别、层与层如何连接、正确选项通常落在哪一层、什么时候不能选最高层。

### 重点记忆模块：十二、错误选项的通用类型

这一节回答“命题人怎样诱导我错、我下次怎样立刻识别”。不要只罗列名称；对每一种与本题有关的干扰项，使用“五联编码”：

| 编码 | 必须讲清的内容 |
|---|---|
| 类型标签 | 给陷阱一个稳定、短小的名称，如“局部细节型” |
| 识别信号 | 看到哪些词、范围或逻辑位置时应警觉 |
| 错误机制 | 它为什么看似正确，究竟偷换了哪一层或哪一关系 |
| 本题映射 | 指明本题哪个选项属于此类，并引用关键证据 |
| 反制动作 | 给出考场上 3—8 秒内能执行的检查动作 |

至少覆盖本题实际出现的类型；通常从以下题库中选择，而不是生硬全部堆入：局部细节型、中间过程型、片面概括型、概念偷换型、因果倒置型、无关项型、绝对化型、范围扩大/缩小型、对策偏离型、过度拔高型、主体错位型、条件关系偷换型。

使用“最小对比对”帮助辨析：把一个错误选项只改动一个关键点变成正确表达，再解释改动为何改变答案。让考生先给选项贴陷阱标签，再展开解析，以提取练习代替被动阅读。

### 让知识真正留下来的教育学机制

围绕上述两个重点模块组织记忆闭环，而不是在结尾泛泛说“多复习”：

- **分块与命名**：把复杂推理压缩为 3—5 个有名称的块，降低工作记忆负担。
- **提取练习**：先隐藏答案，让考生回忆框架节点、陷阱标签与反制动作，再即时反馈。
- **精加工提问**：至少设置一个“为什么”或“如果……会怎样”的自我解释问题，促使新规则连接旧知识。
- **对比学习**：并排比较正确/错误、总体/局部、适用/不适用，突出决定性差异。
- **交错练习**：重构题混合不同主题和相邻陷阱，避免只会识别表面词汇。
- **间隔复习**：在复盘卡给出“10 分钟、1 天、3 天、7 天”的提取任务；每次先回忆后查看。
- **元认知校准**：作答前后记录信心等级，并提示考生比较“感觉会”与“能否说出证据链”。

每个重点模块至少包含 2 个可点击揭晓的记忆问题。问题应要求主动回忆或分类，不能只是“你看懂了吗”。

### 4. 生成重构题

至少生成 1 道重构题，默认生成 3 道分层练习：

- 同构题：更换主题，保留相同解题结构；
- 变式题：改变干扰项或表达方式；
- 迁移题：在相邻题型或更复杂材料中应用同一规律。

每题必须有 A—D 四个选项、唯一正确答案、解析和考点标签。HTML 中练习题也应先选择再揭晓答案。不要仅替换专有名词；题干、论证链和选项陷阱都要重新设计。

### 5. 组织 Markdown 数据

先写完整 Markdown，再构造 `renderer.py` 所需 JSON。Markdown 使用清晰标题、表格、引用和流程箭头；关键规律用 `==高亮==`，同时可用加粗保证普通渲染器可读。

JSON 至少包含：

```json
{
  "title": "标题",
  "category": "言语理解与表达｜意图判断题",
  "question": "题干",
  "options": {"A": "...", "B": "...", "C": "...", "D": "..."},
  "answer": "C",
  "diagnosis": {"A": "...", "B": "...", "C": "...", "D": "..."},
  "sections": [{
    "id": "framework",
    "title": "十一、这类题目的通用逻辑框架",
    "priority": true,
    "html": "已转义和排版的正文 HTML",
    "memory_checks": [{"prompt": "请先回忆……", "answer": "……"}]
  }],
  "practice": [{"question": "...", "options": {"A":"..."}, "answer": "A", "explanation": "...", "tag": "同构题"}]
}
```

正文 `html` 可以使用 `p`、`ul`、`ol`、`table`、`blockquote`、`mark`、`strong`、`code` 与标题标签；内容来自题目分析，不嵌入不受信任脚本。

### 6. 渲染并校验

调用：

```bash
python3 scripts/renderer.py --input <json> --output <html>
```

渲染后执行：

```bash
python3 scripts/validate_output.py --html <html> --markdown <md>
```

校验通过后再打开 HTML。若校验失败，修复内容或结构并重新验证。

## HTML 体验要求

- 桌面端左侧固定目录，右侧阅读内容；窄屏下目录折叠到顶部。
- 目录自动列出原题测试、所有解析章节、重构练习和复盘卡片。
- 当前阅读章节在目录中高亮。
- “十一、通用逻辑框架”和“十二、错误选项类型”使用核心模块样式、醒目标识和目录星标，其视觉权重明显高于普通章节。
- 关键点用醒目但克制的高亮色；正确、错误、提示使用不同颜色。
- 两个核心模块各提供至少 2 个“先回忆—再揭晓”的交互卡，并显示间隔复习计划。
- 支持键盘操作和明显的焦点样式，按钮与单选项有可访问标签。
- 不依赖 CDN、外部字体或网络，单个 HTML 离线可用。
- JavaScript 仅负责答题、反馈、重置、目录状态和学习进度。
- 页首显示学习进度；所有原题与练习完成后显示“本轮掌握完成”。

## 内容质量标准

- 答案必须与题干证据匹配；不确定时明确说明，不伪造权威依据。
- 逐项分析同时判断“内容真假”和“是否回答题干”。
- 概念讲解先用通俗语言，再给抽象框架，最后展示迁移例子。
- 通用逻辑框架必须详细说明节点、识别信号、连接关系、适用边界和跨主题迁移，不得只给公式。
- 错误选项类型必须使用“类型—信号—机制—本题映射—反制动作”五联编码，并包含最小对比对。
- 口诀应短、可执行、能还原推理，不写空泛口号。
- 重构题必须有唯一解，错误选项应对应真实常见误区。
- 全部学习文件使用中文；必要的英文术语后附中文解释。

## 附录：考公思维养成指南

### 各题型对应的政治能力与治理思维

理解每类题目在公务员实际工作中对应的能力，有助于从"应试"转向"思维养成"：

| 题型 | 考查的核心政治能力 | 对应治理思维 | 工作中的实际场景 |
|---|---|---|---|
| 言语理解与表达 | 政策文本解读力、公文规范力 | 精确理解上级意图、准确传达政策 | 阅读理解政策文件、起草公文 |
| 判断推理 | 逻辑严谨性、论证评估力 | 识别因果关系、评估论证有效性 | 分析问题根源、评估方案可行性 |
| 数量关系 | 量化思维、数学模型应用 | 用数据支撑决策、评估方案成本效益 | 预算编制、资源分配、绩效评估 |
| 资料分析 | 数据敏感性、趋势判断力 | 从数据中发现问题、验证假设 | 经济数据分析、政策效果评估 |
| 常识判断 | 政治素养、政策敏感度 | 对国家大政方针的理解和认同 | 理解政策背景、把握工作方向 |
| 申论 | 综合分析力、对策设计力、公文写作力 | 发现问题→分析原因→提出对策→规范表达 | 写调研报告、起草工作方案 |

### 从考生到治理者的思维转变

| 考生思维（需要纠正的） | 治理者思维（需要培养的） |
|---|---|
| "这道题在考我知不知道" | "这道题在测我能不能准确判断" |
| "两个选项差不多，随便选一个" | "两个选项的差异正是区分能力的关键点" |
| "做对就行，不管为什么" | "知道为什么对，比做对更重要" |
| "看材料找答案" | "理解材料的论证结构，答案自然显现" |
| "申论就是写作文" | "申论是用文字解决治理问题" |
| "多刷题就能提分" | "理解命题逻辑才能真正提分" |

### 每日思维训练建议

1. **政策阅读 15 分钟**：每天读一篇国务院政策文件，标注其"问题—分析—对策"结构。
2. **逻辑拆解 5 道题**：不只做对，还要写出每道题的论证链和干扰项设计逻辑。
3. **申论思维一条**：每天用 100 字回答一个"为什么"开头的治理问题。
4. **错题元认知**：每错一道题，先不查解析，自己写："我犯的是什么类型的错误？命题人用什么方法让我选错？"

记住：**公务员考试筛选的不是"知识量"，而是"思维质量"。**
