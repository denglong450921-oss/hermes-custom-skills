# thinking-models-dl — 思维模型工具箱

> 86条思维模型的分类库。当你在写作或分析时，自动识别话题适用的思维模型，提供结构化的分析框架。

## 触发条件

此 skill 在以下场景**必须**加载：

- **写作 Dennon 风格文章时**：分析话题 → 识别可用的思维模型 → 选择 2-4 个核心模型作为文章的分析骨架
- **分析任意话题时**（不仅是写作）：对问题进行系统拆解 → 匹配适用的思维模型 → 输出结构化分析框架

**不触发场景**：用户仅搜索某个模型的定义时（可直接用参考文件查询，不需 skill 介入）

## 与 dennon-perspective 的关系

`thinking-models-dl` 和 `dennon-perspective` 互补使用：

| 维度 | dennon-perspective | thinking-models-dl |
|------|-------------------|-------------------|
| 角色 | 写作框架执行者 | 思维模型提供者 |
| 职责 | 文章结构、章节密度、布局多样性 | 话题→模型匹配、分析框架设计 |
| 输出 | 完整文章 | 模型推荐 + 分析结构建议 |

**使用流程**：加载 dennon-perspective 写文章时，同时加载 thinking-models-dl → dennon-perspective 负责文章结构和表达，thinking-models-dl 负责识别话题涉及哪些思维模型 → 两者协作输出。

## 核心机制：话题→模型匹配

### 输入：话题关键词

从用户提供的话题/问题中提取核心关键词。例如：
- 「差生为什么成绩差」→ 关键词：学习、效率、激励、反馈、系统
- 「熬夜刷手机」→ 关键词：时间定价、延迟满足、多巴胺、注意力

### 匹配规则

按以下优先级从 86 个模型中筛选 2-4 个：

1. **直接命中**：话题关键词与模型的分类标签/核心概念直接匹配
2. **结构关联**：话题呈现的底层结构与某个模型的解释框架一致
3. **反常识入口**：找到与大众直觉相反的模型作为「认知纠偏」入口
4. **递进组合**：挑选的 2-4 个模型之间形成递进关系（基础→进阶→高阶）

### 输出格式

```markdown
## 适用模型
1. **[模型名]** — 一句话定义
   - 为什么匹配这个话题
   - 在文章中如何展开
2. **[模型名]** — 一句话定义
   - ...
```

**模型推荐数量**：完整文章 2-4 个，快速分析 1-2 个。多于 4 个会稀释分析深度。

## 写作中的模型使用方法

### 方法一：作为文章的「系统模型」章节

Dennon 文章结构中，第三章通常是系统模型（立）。此时将匹配到的 1-2 个核心模型作为系统框架展开：

```
## [模型名]：理解这个问题的系统框架

模型定义 → 用话题案例解释 → 揭示的深层机制 → 对读者的启示
```

### 方法二：作为「破」的入口

用某个反直觉的模型作为认知纠偏的入口：

```
大多数人认为[直觉认知]。
但[模型名]告诉我们，实际上是[模型推导出的结论]。
```

例如：用「二阶思维」来破「刷手机=放松」→ 刷手机的后果的后果（注意力碎片化、多巴胺阈值升高）才是真正代价。

### 方法三：作为「递进」的骨架

用 2-3 个递进关系的模型构建文章的渐进结构：

```
第一层：[模型A]——理解基础机制
第二层：[模型B]——理解驱动因素
第三层：[模型C]——找到杠杆点
```

### 方法四：作为「金句收束」的来源

模型的精炼定义本身就是强判断句，可直接作为引用块或结尾金句：

> 「你不需要等待任何人的许可，就可以开始使用这些模型。你自己就是起点。」

## 输出规范

- 模型推荐总字数：完整文章约 100-300 字（简述匹配理由），快速分析约 50-100 字
- 每次输出**必须**说明为什么选择这些模型——不是列清单，是解释关联
- 不输出未经匹配的模型列表（不在分析时说「还有以下模型可用」）
- 格式优先用编号列表 + 引用块 + 短段落，不用表格（模型推荐本身不需要对比表）
