# FAQ Decision Tree: Does Your Skill Need an FAQ?

Run each sub-skill through this 7-node tree to decide whether to add a FAQ section.

```
START
  |
  v
[准备写 / 拆分子 Skill 文档]
  |
  v
+------------------------------------------------+
| 1. 文档是否很短、流程是否很简单？               |
|    例：只有一个输入、一个步骤、一个输出          |
+------------------------------------------------+
  |-- YES --> +------------------------------------+
  |           | 是否几乎不会产生误解？             |
  |           +------------------------------------+
  |              |-- YES --> [可以不写 FAQ]
  |              |              |
  |              |              v
  |              |        [保持文档简洁即可]
  |              |
  |              |-- NO
  |                    |
  |                    v
  |              [建议添加 FAQ]
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 2. 是否容易被用户 / Agent 理解错？              |
|    例：不知道能不能单独运行、先跑哪个 Skill      |
+------------------------------------------------+
  |-- YES --> [需要 FAQ]
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 3. 是否有明确前置条件？                         |
|    例：必须先完成环境初始化                      |
+------------------------------------------------+
  |-- YES --> [需要 FAQ 或"前置条件"说明]
  |            |
  |            v
  |         FAQ 示例：
  |         Q: 如果没有完成环境初始化怎么办？
  |         A: 先运行 Init Skill，不要直接执行当前 Skill。
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 4. 这个子 Skill 是否可能被单独调用？             |
|    也就是脱离主流程也能跑                        |
+------------------------------------------------+
  |-- YES --> [建议添加 FAQ]
  |            |
  |            v
  |         FAQ 示例：
  |         Q: 这个子 Skill 可以单独运行吗？
  |         A: 可以，但需要满足输入和前置条件。
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 5. 这个 Skill 的职责边界是否容易混淆？           |
|    例：数据处理 Skill 是否也要负责导出？         |
+------------------------------------------------+
  |-- YES --> [需要 FAQ]
  |            |
  |            v
  |         FAQ 示例：
  |         Q: 这个 Skill 负责哪些事情？
  |         A: 只负责数据处理，不负责环境配置和最终导出。
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 6. 是否经常会重复问同类问题？                   |
|    例：先跑哪个、输出什么、失败怎么办            |
+------------------------------------------------+
  |-- YES --> [需要 FAQ]
  |            |
  |            v
  |         [把重复问题提前写进文档]
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 7. 是否希望子 Skill 更稳定、可复用？             |
+------------------------------------------------+
  |-- YES --> [建议添加 FAQ]
  |
  |-- NO --> [可以省略 FAQ]
        |
        v
+------------------------------------------------+
| FINAL DECISION                                  |
+------------------------------------------------+
  |
  +--> [不需要 FAQ]
  |       |
  |       v
  |    适合情况：
  |    - 文档很短
  |    - 流程简单
  |    - 没有前置条件
  |    - 不容易误解
  |
  +--> [需要 FAQ]
          |
          v
       适合情况：
       - 有前置条件
       - 有多个子 Skill
       - 有依赖顺序
       - 容易跑偏
       - 需要独立复用
       - 经常重复解释

          |
          v
+------------------------------------------------+
| 推荐文档结构                                    |
+------------------------------------------------+

# Skill Name

## 作用
这个 Skill 只负责什么。

## 前置条件
必须先完成什么。

## 输入
需要什么材料。

## 输出
会产出什么结果。

## 执行步骤
1.
2.
3.

## 常见问题 FAQ
Q:
A:
```

## When to Apply

This tree is most useful after completing a harness injection (skill-harness Step 1/1b). The harness verifies format correctness — this tree verifies documentation completeness.

Typical trigger: you've added evals/ to a skill, but a user or sub-agent keeps asking the same clarifying questions. That's a signal the skill needs an FAQ.
