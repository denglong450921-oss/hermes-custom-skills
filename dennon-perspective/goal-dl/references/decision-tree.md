# Decision Tree: Goal Writing Walkthrough

Run your goal through this 11-node decision tree. Each node maps to a principle in the 7-principle framework.

```
START
  |
  v
[准备写 Codex Goal Prompt]
  |
  v
+------------------------------------------------+
| 1. 目标是否清晰、可验证？                       |
|    是否能判断"什么时候算完成"？                 |
+------------------------------------------------+
  |-- NO --> [先不要直接开跑]
  |           |
  |           v
  |        [先讨论 / 让 Codex 在 plan mode 中帮你定义 goal]
  |
  |-- YES
        |
        v
+------------------------------------------------+
| 2. 是否有明确数字或退出标准？                   |
|    例：降低 30%、100% 测试对等、通过 N 个 eval   |
+------------------------------------------------+
  |-- NO --> [补充可量化标准]
  |           |
  |           v
  |        [把目标改成可检查的完成条件]              ← Principle 1
  |
  |-- YES
        |
        v
+------------------------------------------------+
| 3. 是否给了足够方向？                           |
|    起点 / 可用工具 / 已知限制 / 容易走偏的地方   |
+------------------------------------------------+
  |-- NO --> [补充上下文]
  |           |
  |           v
  |        [必要时先让 Codex 调研并生成 plan 文件]   ← Principle 2
  |           |
  |           v
  |        [再让 goal prompt 引用该 plan]
  |
  |-- YES
        |
        v
+------------------------------------------------+
| 4. 进展是否可衡量？                             |
|    是否有测试、eval、截图 diff、性能指标等工具？ |
+------------------------------------------------+
  |-- NO --> [先建立衡量方式]
  |           |
  |           v
  |        [避免只靠主观判断"看起来完成了"]          ← Principle 3
  |
  |-- YES
        |
        v
+------------------------------------------------+
| 5. 是否存在"假完成"风险？                       |
|    例：裁切设计图冒充 pixel perfect             |
|        砍测试覆盖率凑 100% 通过                 |
+------------------------------------------------+
  |-- YES --> [在 prompt 中明确禁止取巧路径]
  |            |
  |            v
  |         [要求保留测试覆盖、真实实现、可复现证据]  ← Principle 3 (anti-fake)
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 6. 是否能在真实或接近生产的环境中运行？          |
|    同技术栈 / 同 flags / 相似数据库 / 测试环境   |
+------------------------------------------------+
  |-- NO --> [补齐真实环境条件]
  |           |
  |           v
  |        [否则只能得到演示级结果，不一定是真进展]   ← Principle 4
  |
  |-- YES
        |
        v
+------------------------------------------------+
| 7. 这个目标是否主要是"纯视觉还原"？             |
|    例：100% 像素级复刻 UI                       |
+------------------------------------------------+
  |-- YES --> [慎用纯视觉目标]
  |            |
  |            v
  |         [把图片作为上下文]
  |            |
  |            v
  |         [改用功能清单 / 规格 / 设计系统判断达成]  ← Principle 5
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 8. 任务是否会跑很久？                           |
|    几小时 / 几天 / 后台持续执行                 |
+------------------------------------------------+
  |-- YES --> [设置进展跟踪机制]
  |            |
  |            +--> [关键节点 commit]
  |            +--> [推 draft PR]
  |            +--> [更新老板可看的产物：HTML / 图 / Markdown]
  |            +--> [同步到 Slack]
  |            +--> [用 /side 临时侧聊查状态]        ← Principle 6
  |
  |-- NO
        |
        v
+------------------------------------------------+
| 9. Codex 是否声称已经完成？                     |
+------------------------------------------------+
  |
  v
+------------------------------------------------+
| 10. 是否经过本地 review？                       |
|     尤其是优化、迁移、重构类任务                 |
+------------------------------------------------+
  |-- NO --> [先 /review 本地评审]
  |           |
  |           v
  |        [要求 Codex 自查是否真的满足退出标准]     ← Principle 7
  |
  |-- YES
        |
        v
+------------------------------------------------+
| 11. 是否清理了无效尝试和临时代码？              |
|     是否删除了试过但没用的改动？                 |
+------------------------------------------------+
  |-- NO --> [让 Codex 回看并清理]
  |           |
  |           v
  |        [保留必要改动，删除实验垃圾]              ← Principle 7
  |
  |-- YES
        |
        v
+------------------------------------------------+
| FINAL: 可以交给团队 / 合并 / 部署               |
+------------------------------------------------+
```
