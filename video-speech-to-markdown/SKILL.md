# 视频语音转 Markdown

把视频中的中文、英文或中英混合语音转成结构清楚、可追溯的 Markdown 文稿。核心目标是忠实记录可听内容，不把猜测伪装成原话。

## 默认行为

- 输入：一个本地视频文件。
- 支持：MP4、MOV、MKV、WebM、M4V、AVI 等 `ffmpeg` 可读取格式。
- 语言：默认自动识别；支持中文、英文和中英混合语音。
- 输出：与视频同目录的同名 `.md`；若用户指定目录或文件名，以用户要求为准。
- 内容：文件信息、识别信息、带时间戳逐段转写、连续全文和质量备注。
- 翻译：默认不翻译，保持说话者使用的语言；用户明确要求时才增加翻译。
- 时间戳：默认每个识别片段一个起止时间。

## 开始前解析任务

先确认四件事：

1. **视频路径**：必须解析到唯一、存在且可读的文件。
2. **输出路径**：不得无意覆盖现有文件；目标已存在时生成带时间戳的新文件，除非用户明确允许覆盖。
3. **语言模式**：
   - 未指定：使用 `auto`；
   - 明确全中文：使用 `zh`；
   - 明确全英文：使用 `en`；
   - 中英混合：使用 `mixed`，脚本会按静音边界切块并逐块识别语言。
4. **输出粒度**：默认时间戳逐段稿；用户要求“纯文本”时仍输出 Markdown，但可省略逐段时间戳。

若多个视频都可能是目标，或文件不存在，停止转写并请用户明确目标。不要猜文件。

## 标准工作流

### 1．检查视频

运行：

```bash
ffprobe -v error -show_entries format=duration:stream=codec_type,codec_name \
  -of json "<video>"
```

确认：

- 文件可读取；
- 至少有一个音频流；
- 时长大于 0；
- 输出目录可写。

没有音频流时不要制造空转写稿。报告“视频不含可识别音轨”，并保留原文件不变。

### 2．先生成资源处理计划

不要拿到任何视频都直接整段推理。脚本必须先根据时长、文件大小、语言模式与系统内存选择策略：

| 视频条件 | 默认模式 | 批次策略 | 模型策略 |
|---|---|---|---|
| ≤ 90 秒且 ≤ 200 MB | 整段 | 单批处理 | `medium`，低内存时 `base` |
| 90 秒—15 分钟 | 分批 | 约 30 秒，在附近静音处分割 | `medium`，失败批次降级 `base` |
| 15—60 分钟 | 分批 | 约 45 秒，在附近静音处分割 | 按内存选 `medium/base` |
| > 60 分钟或超大文件 | 分批 | 约 60 秒，逐批落盘 | 优先稳定性，可用 `base` |
| 中英混合 | 分批 | 每批独立检测语言 | 保留原语言 |

视频分辨率不应直接增加识别负担：先统一提取为 16 kHz、单声道 WAV。文件大小主要用于预估解码与磁盘资源，时长主要决定推理批次。

页面或回复中说明最终计划，包括：整段/分批、批次数、批长、模型和降级策略。

### 3．运行内置脚本

优先使用本技能的确定性脚本：

```bash
python3 scripts/transcribe_video.py \
  --input "<video>" \
  --output "<transcript.md>" \
  --language auto \
  --model auto \
  --mode auto
```

明确是中英混合视频时运行：

```bash
python3 scripts/transcribe_video.py \
  --input "<video>" \
  --output "<transcript.md>" \
  --language mixed \
  --model medium
```

速度优先时可用：

```bash
python3 scripts/transcribe_video.py \
  --input "<video>" \
  --output "<transcript.md>" \
  --model base
```

准确率优先、音频噪声较多或专业词较多时，使用本机已缓存的更大模型；不要为了“更准确”静默下载数 GB 模型。若模型未缓存且下载会明显耗时，先告知用户。

#### 分批、断点与容错机制

- 时长超过 90 秒时默认分批，不允许先尝试整段、失败后才补救。
- 分割点优先落在目标时长附近的静音处，避免从词语中间切断。
- 每一批在独立子进程中推理；批次结束即释放模型内存，避免连续视频造成内存累积。
- 每完成一批，立即把识别文本、语言、置信度和使用模型原子写入隐藏工作目录。
- 同一输入和计划重跑时，自动复用已完成批次，只处理未完成批次。
- 单批失败时依次尝试：
  1. 原模型＋语音活动检测；
  2. 原模型关闭语音活动检测；
  3. `base` 后备模型。
- 进程被系统终止时，重新运行相同命令，从最近断点继续，不从头重做。
- 只有全部批次完成后才生成最终 Markdown；不能把半成品当作完成结果。

### 4．输出后执行双层校验

运行：

```bash
python3 scripts/validate_transcript.py "<transcript.md>" --strict
```

#### 第一层：结构与时间轴校验

- Markdown 非空；
- 包含文件信息、处理计划、逐段转写、连续全文和质量报告；
- 时间戳递增，起点不晚于终点，不存在异常大范围重叠；
- 分段文本与连续全文逐字一致；
- 完成批次数与计划批次数一致；
- 不含脚本错误、模型日志或临时路径。

#### 第二层：文本质量校验

脚本先检查：

- 低置信片段及对应时间；
- 相邻重复或疑似循环幻觉；
- 中英文语言是否按原语言保留；
- 中文标点是否经过规范化；
- 是否发生模型降级。
- 批次尾部文本不得越过该批时间边界；短于 0.7 秒且低置信，或“无语音概率高＋低置信”的尾部内容按静音幻觉剔除。
- 更大模型不是自动真值。若大模型输出与音频时长、上下文或无语音概率冲突，应拒绝该结果。

然后由执行者分块阅读全文，进行语义一致性复核：

1. 建立高频术语表，检查同一概念是否出现多个近音写法；
2. 检查人名、理论名、产品名、数字、否定词和专业术语；
3. 对可疑片段回到时间戳，使用更大模型和 `--initial-prompt` 单独重跑；
4. 只有上下文或复识别证据充分时才校订，不能凭感觉改写；
5. 把确认的修改写入 JSON，使用：

```bash
python3 scripts/apply_corrections.py \
  --markdown "<raw.md>" \
  --corrections "<corrections.json>" \
  --output "<validated.md>"
```

校订后的 Markdown 必须新增“校订记录”，再运行一次严格校验。若严格校验仍为 `WARN` 或 `FAIL`，不要报告“已完成”；列出未通过项和对应时间戳。

### 5．交付

给出 Markdown 的绝对路径链接，并简要说明：

- 检测语言；
- 视频时长；
- 使用模型；
- 处理模式与批次数；
- 结构校验和文本质量校验结果；
- 是否存在低置信、听不清或可能需人工复核的片段。

## Markdown 输出格式

保持以下结构：

```markdown
# 视频转写：标题

## 文件信息

- 来源视频：`example.mp4`
- 视频时长：00:12:34
- 识别语言：中文 / English / 中英混合
- 转写模型：medium
- 生成时间：YYYY-MM-DD HH:MM

## 处理计划

- 处理模式：chunked
- 资源策略：按静音边界分批
- 分批数量：25
- 断点目录：`.example.transcribe-work`

## 带时间戳转写

### [00:00:00 → 00:00:08]

第一段转写内容。

### [00:00:08 → 00:00:15]

Second transcript segment.

## 连续全文

第一段转写内容。Second transcript segment.

## 转写质量报告

- 质量结论：PASS
- 已完成批次：25/25
- 低置信片段：0
- 相邻重复：0
- 模型降级：0

## 质量备注

- 自动转写可能误识别人名、地名、缩写和专业术语。
- 建议人工复核标记为“听不清”的片段。
```

## 转写质量原则

### 忠实优先

- 保持原语言，不自动翻译或润色成另一种意思。
- 修正常见的模型空格与重复片段，但不要改写说话者观点。
- 不凭上下文补造未听清的人名、数字、机构或专业词。
- 若片段无法可靠识别，写作 `[听不清]`，并保留时间戳。

### 可读但不篡改

默认做轻量整理：

- 合并明显属于同一句的碎片；
- 中文使用合适的句读，英文保留自然标点；
- 删除纯填充噪声或模型重复；
- 保留有意义的口头语、否定、数字和语气转折。

用户要求“逐字稿”时减少清理，保留重复、停顿词和口语特征。用户要求“整理稿”时，可另加“内容提要”，但不能用摘要替代转写正文。

### 中英混合

- 不把英语术语强行音译为中文。
- 不把中文人名或专有名词强行翻成英文。
- 代码、缩写、产品名和数字尽量保留原形。
- 自动识别结果明显把另一种语言误写成同音字时，在质量备注中指出，不静默猜改。

## 可选功能

用户明确要求时才启用：

- `--translate-to zh`：在原文之后增加中文翻译；
- `--translate-to en`：在原文之后增加英文翻译；
- `--no-timestamps`：只输出连续文本；
- `--language mixed`：按静音边界切段，每段独立检测中文或英文；
- `--initial-prompt`：为课程名称、人名、专业词提供上下文；
- `--model base|medium|large-v3`：选择速度与准确率。
- `--mode auto|direct|chunked`：自动规划、强制整段或强制分批；
- `--chunk-seconds N`：覆盖默认批次长度；
- `--work-dir PATH`：指定断点目录；
- `--reset-work`：输入或计划改变后清除旧断点并重建。

内置脚本只负责忠实转写；翻译和内容摘要应在转写校验通过后进行，并与原文分区展示。

## 失败恢复

| 问题 | 处理 |
|---|---|
| 找不到 `ffmpeg` 或 `ffprobe` | 报告缺失依赖和安装命令；不要声称已完成 |
| 找不到 `faster-whisper` | 报告 `python3 -m pip install faster-whisper`；不要输出伪转写 |
| 视频没有音轨 | 明确报告无音轨并停止 |
| 模型未缓存且网络不可用 | 改用已缓存模型；没有可用模型时报告阻塞 |
| 音轨无法解码 | 用 `ffmpeg` 单独导出 WAV 重试一次；仍失败则保留错误信息 |
| 输出路径已存在 | 生成新文件名或请求覆盖许可 |
| 转写为空 | 检查音量与音轨；若确实无可识别语音，输出失败报告而非空 Markdown |
| 单批异常退出 | 从断点恢复该批；关闭 VAD 重试；仍失败则改用 `base` |
| 整个进程被系统终止 | 重跑同一命令，复用已完成批次；不要删除工作目录 |
| 大量低质量片段 | 提取可疑时间段，用更大模型＋术语提示重跑，再写校订记录 |
| 严格校验为 WARN/FAIL | 不交付为完成；修复具体项目后从校验步骤重跑 |

## 完成前检查

- 输入视频唯一且存在；
- 视频包含有效音频流；
- 已按大小、时长和内存生成资源计划；
- 中长视频使用分批机制；
- 每批结果已落盘，可断点续跑；
- Markdown 已生成且非空；
- 时间戳递增且格式统一；
- 中英文保持原语言；
- 未将推测写成确定原话；
- 连续全文与分段稿内容一致；
- 专名、数字、否定与高频术语已做语义一致性复核；
- 结构校验和文本质量严格校验都通过；
- 若做过修正，Markdown 包含校订记录；
- 最终回复提供可点击的绝对路径。
